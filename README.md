### 📘 『기술노트』 구간 (2~3회차)

**모임 전 — 주제 올리기**
- 이번 회차 범위에서 아래 중 하나를 골라 **제한없이** [Issue](../../issues)에 올립니다.
  - 서로 공유하고 싶은것
  - 이야기해 볼 만한 것 (흥미로운 것, 같이 생각해 보고 싶은 것)
  - 내가 알고 있는 것을 설명해 보고 싶은 것
- 이미 올라온 주제와 질문 상관없이 **상관없이 올립니다.** (중복 상관없음)
- 마감은 **매주 금요일**입니다.

**모임**
- 이슈에 대해서 다 같이 모르는 부분과 궁금한 점을 이야기합니다.


### 🎤 『프런트엔드 면접의 기술』 구간

한 주에 **1명이 1명에게 질문 1개**를 하고, **1명이 1개의 질문에 답합니다.**
4명이니 매주 질문은 4개, 1개당 약 15분입니다.

**모임 전 — 질문하기**
- 이번 회차 범위에서 궁금한 질문 1개를 골라, **질문 순서표의 상대에게** [Issue](../../issues)로 남깁니다.
- 책 문장을 그대로 옮기기보다, "이건 왜?", "그럼 이건?"처럼 **스스로 만든 질문**이면 좋습니다.
- 질문 마감은 **매주 금요일**입니다. 답할 사람이 준비할 시간을 주기 위해서입니다.

**모임 전 — 답 준비하기**
- 받은 질문을 책, 공식 문서, AI, 직접 짠 코드로 공부해 옵니다.
- 답은 **자신의 Notion 페이지**에 정리하고, 이슈에 링크를 남깁니다.

**모임 (질문 1개당 약 15분)**
- 답하는 사람이 **메모 없이 자기 말로** 면접처럼 답합니다.
- 질문한 사람과 나머지 2명이 **꼬리 질문**을 던집니다.
- **질문과 답**으로만 진행합니다.

**모임 후**
- **답한 사람**이 이슈에 답을 **출처와 함께** 정리(또는 Notion 링크를 첨부)하고 이슈를 닫습니다.
- 모임에서 답이 나오지 않은 꼬리 질문은 **새 이슈로** 만들고 `꼬리 질문` 또는 `검증 필요` 라벨을 달아 열어둡니다.

> **열린 이슈 = 아직 우리가 모르는 것**입니다.

## ✅ 팩트 체크 규칙

서로 찾아온 정보가 맞는지 확인하기 위한 규칙입니다.

1. **답변에는 출처를 1개 이상 답니다.**
   MDN, 공식 문서, 책 페이지 등을 적습니다. AI의 답은 출처가 아니라 **가설**입니다.
2. **확신이 없으면 `검증 필요` 라벨을 답니다.**
   이런 질문은 직접 코드로 확인하거나, 멘토링 시간에 질문합니다.

## 📝 기록 방식

기록은 **GitHub 이슈**와 **Notion**으로 나눠서 합니다.

| 무엇을 | 어디에 | 누가 |
| --- | --- | --- |
| 질문·주제, 꼬리 질문 | GitHub 이슈 | 올리는 사람 |
| 회의록 | Notion | 회차별로 돌아가며 작성 후 링크 공유 |
| 질문에 대한 답 | 자신의 Notion 페이지 → 이슈에 링크 첨부 | 답한 사람 |
| 이슈 링크 모음 | Notion 스터디 페이지 | 각자 |
